1. WHAT THIS IS
-------------------------------------------------------------------------------
A festive web app where anyone can post a Christmas wish. Two ways wishes are
found:

  1. NAME SEARCH   - a visitor types a first name + surname; they see the wish
                     cards that person chose to make findable by their real name.

  2. PUBLIC SNOWFIELD (the home page) - a calm dark winter-night canvas with
                     falling snow. Wishes that were NOT opted into name-search
                     drift here as half-buried paper notes, signed with an
                     ALIAS. You drag/pan around the field and click a note to
                     unfold and read it. You might stumble on your own.

Per-wish identity (rev 2, dual-faceted): every wish collects first name +
surname + alias. The alias is ALWAYS what shows on the public snowfield; real
names are never sent to the field API. A "Let people find this by my name"
checkbox (default on) sets `searchable` - when off, the wish still drifts on the
field under its alias but the name cannot be looked up in /search.

Moderation model: auto-publish + a best-effort profanity wordlist filter.
Anyone can "report" a wish; 3 reports auto-hides it. A secret-gated /admin page
can hide / un-hide anything.

3. HOW IT'S BUILT
-------------------------------------------------------------------------------
STACK
  - Next.js 16 (App Router, TypeScript, Turbopack) - front end + API routes in
    one project.
  - React 19.
  - Tailwind CSS v4 (@import "tailwindcss" in app/globals.css) + a bit of custom
    CSS for the paper notes and the falling-snow layers.
  - @supabase/supabase-js - single anon-key client (lib/supabase.ts).
  - zod - request validation (lib/validation.ts).
  - next/font/google - Geist (UI) + Caveat (the handwritten "--font-hand").

DATA MODEL  (Supabase, schema: public)
  table wishes   (rev 2 - dual-faceted)
    id            uuid  pk  default gen_random_uuid()
    body          text  not null, 1..500 chars
    first_name    text  NOT NULL
    last_name     text  NOT NULL
    alias         text  NOT NULL
    searchable    boolean NOT NULL default true  - is the real name discoverable
    name_search   text  GENERATED: when searchable -> lower(trim(first)||' '||
                        trim(last)); else NULL (so opted-out wishes never match).
                        Indexed - this is what /search matches on.
    x, y          double precision NOT NULL - stable snowfield position, assigned
                        server-side for EVERY wish (all wishes drift on the field).
    status        text  'visible' | 'hidden'  (default 'visible')
    report_count  int   default 0
    created_at    timestamptz default now()
    CHECK names_present: first/last/alias all non-blank.
    indexes: (name_search); partial (created_at desc) where status='visible'.

  table app_config (key text pk, value text)
    - holds the admin secret. RLS enabled with NO policies => unreachable by the
      anon/authenticated roles; only SECURITY DEFINER functions can read it.

  ROW LEVEL SECURITY on wishes:
    - SELECT: allowed only where status = 'visible'  (public read).
    - INSERT / UPDATE: no policy => denied to anon. All writes go through
      SECURITY DEFINER rpc functions instead:
        create_wish(body, first, last, alias, searchable, x, y) -> wishes
        report_wish(id)          -- +1 report_count, auto-set status='hidden' at 3
        admin_list_wishes(secret)             -- returns up to 200 rows, all statuses
        admin_set_status(secret, id, status)  -- hide / un-hide
      admin_* functions compare `secret` against app_config before doing anything.

MIGRATIONS APPLIED (via Supabase MCP, in order):

    wish_rpcs              - create_wish, report_wish (+ grants)

REQUEST FLOW - creating a wish:
    Browser (components/WishComposer.tsx)
      -> POST /api/wishes (app/api/wishes/route.ts)
         - zod parse (lib/validation.ts)
         - profanity check on body/alias/name (lib/profanity.ts) -> 422 if hit
         - if alias: randomPosition() within FIELD bounds (lib/field.ts)
         - supabase.rpc('create_wish', ...)
      -> returns the new row; UI shows a success screen. For alias wishes the
         "Find it in the field" link is /?focus=<id>, which the snowfield uses
         to centre the view on that note.

REQUEST FLOW - the snowfield:
    app/page.tsx (server) renders <Snow/> + <SiteHeader/> + <SnowField/> (client,
    wrapped in <Suspense> because it uses useSearchParams).
    components/SnowField.tsx:
      - on mount, pages through GET /api/wishes/field?cursor=... (keyset paging
        on created_at, 60/page, cap ~400) into one array.
      - centres the viewport on ?focus=<id> if present, else on the centroid of
        loaded notes.
      - notes are absolutely positioned on a FIELD.width x FIELD.height plane
        (lib/field.ts, currently 2600x1800); the plane is panned by mutating a
        translate() transform on pointer drag / arrow keys (offset is clamped so
        you can't pan past the edges).
      - deterministic per-note rotation from a hash of the id.
      - click (when not dragging) opens a modal reusing <WishCard/>, which has
        the "report" button -> POST /api/wishes/<id>/report.

NAME SEARCH:
    components/NameSearch.tsx -> GET /api/wishes/search?first=&last=
    -> app/api/wishes/search/route.ts does a direct supabase.from('wishes')
       .select(...).eq('visibility','named').eq('status','visible')
       .eq('name_search', `${first} ${last}`)  (both lowercased+trimmed).
    Exact match on the normalised full name. Empty state if nothing.

ADMIN:
    app/admin/page.tsx (client) - password field, token kept in sessionStorage.
    -> GET  /api/admin/wishes           (header x-admin-token)
       POST /api/admin/wishes {id,status}
    app/api/admin/wishes/route.ts checks the header against process.env.ADMIN_SECRET,
    then calls admin_list_wishes / admin_set_status with the same secret.
    Not linked from anywhere in the UI - you navigate to /admin directly.

STYLING NOTES (app/globals.css):

    - .note-paper: cream gradient card + shadow; ::after draws a white radial

    - .snow-a / .snow-b: two fixed full-screen layers of radial-gradient dots,
      animated by shifting background-position-y; disabled under

    - .font-hand: Caveat, used for the title, wishes, and signatures.
